Task 2- Causal Tracing & Activation Patching
To identify which layer in the model is responsible for recalling a fact.

Key concepts for understanding:
1. Layers (Qwen/Qwen2.5-1.5B-Instruct has 28 layers)
Transformers architechture - Inpute -> Layer1 -> Layer 2 -> .... -> output
The model consists of multiple layers that process information step by step.
2. Activations
Each layer produces an internal representation - activation="What the model currently knows/thinks at this step".
The facts are encoded in activations across layers.
3. Clean vs Corrupted Runs
Clean run: model behaves normally and produces correct output
Corrupted run: input is modified to disrupt the correct answer

What Was Implemented:
Step 1: Clean Run
Prompt example: "The capital of France is"
Model produces correct answer ("Paris")
Activations from all layers are saved\

Step 2: Corrupted Run
Modified prompt: "The capital of France is not"
Model produces incorrect or weaker answer
Activations are saved again

Step 3: Activation Patching
For each layer:
Run the corrupted model
Replace that layer's activation with the clean activation
Measure if the correct answer is restored

Final Outcome:
The layer with the highest score is selected as:
The most important layer for that fact

Proper pipeline of tasks

Think of the project as six connected stages:

Stage 1: Repo and environment

Set up the codebase so everyone can run the same commands.

Stage 2: Data pipeline

Prepare CounterFact, paraphrases, and consistency queries.

Stage 3: Localization pipeline

Use causal tracing to find which layers store the fact.

Stage 4: Editing pipeline

Implement and run ROME, MEMIT, and LoRA.

Stage 5: Evaluation pipeline

Measure ESR, PG, LL, CS, and IR.

Stage 6: Analysis + reporting

Create tables, plots, examples, and final writeup.

That ordering matters because the later stages depend on the earlier ones.

3-week timeline
Week 1: Get the pipeline working end-to-end

Goal: every component runs on a small subset.

Member 1

Set up environment, dependencies, scripts, and GPU sanity checks.
Make a single inference script for the chosen model.
Write the run instructions in the repo README.

Member 2

Implement causal tracing / activation patching.
Verify that the expected mid-layer behavior appears.
Save layer-wise activation outputs.

Member 3

Finish ROME integration on a tiny subset.
Confirm one fact can be edited successfully.
Log target prompt, edited prompt, and paraphrases.

Member 4

Scaffold MEMIT code path.
Run a toy batch edit and confirm no crashes.
Identify layer-spread settings to test later.

Member 5

Build the evaluation harness for ESR, PG, LL, CS, IR.
Start plotting templates and result logging format.
Prepare consistency query examples.

End-of-week checkpoint

One shared script can run:
    load model,
    load one fact,
    apply one edit,
    evaluate at least ESR and PG.
